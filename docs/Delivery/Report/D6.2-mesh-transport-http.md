## 3. Key Design Decisions

### 3.1 Wire Protocol — HTTP + msgpack
- Envelopes are binary‑encoded with msgpack (`@msgpack/msgpack`) and sent as HTTP request/response bodies.
- Envelope fields (`scopeId`, `headers`, `body`, `signature`) are **mirrored in HTTP headers** so intermediaries can route/validate without deserialization.
- Header names use the `X-Mesh-` prefix (`X-Mesh-Scope-Id`, `X-Mesh-Envelope-Body-Sig`, etc.).

### 3.2 Security
- **Scope‑based signing:** The sender signs SHA‑256(body) with their Ed25519 key pair (via `@orqenix/crypto`). The recipient verifies the signature against the sender's public key.
- **Forged‑scope detection:** If Alice sends from scope `S`, the server validates that Alice's key is authorised for scope `S`. A mismatch denies the request (`C1`, `C5`).
- **Header/body integrity:** The body HMAC in `X-Mesh-Envelope-Body-Sig` must match the actual body; mismatch yields `E_ENVELOPE_MISMATCH` (`C6`).

### 3.3 Deduplication (`C3`, `C8`)
- A fixed‑size LRU cache keyed by `(senderScopeId, envelopeId)`.
- If the same envelope arrives twice (e.g. retransmission), the second call is silently dropped.
- Cache capacity is bounded (default 10 000 entries) and evicts oldest on overflow.

### 3.4 Deadlines / Timeouts (`C4`)
- Client operations accept an optional `signal` (AbortSignal) or a `deadline` timestamp.
- A `setTimeout`-based watchdog cancels the HTTP request when the deadline fires.
- The server also enforces a per‑request timeout (configurable via `serverOptions.requestTimeoutMs`).

### 3.5 Retry (`C7`)
- `HttpMeshClient` applies retry only for **transient failures** (network errors, timeouts).
- **Semantic denials** (forged scope, bad signature) are never retried.
- Retry uses exponential backoff with jitter: `baseDelay * 2^attempt + random(0, jitter)`.

### 3.6 Identity
- `getSelfId()` returns the local `ScopeId` with a description including the bound address.
- `getRemoteId()` reads `X-Mesh-Scope-Id` from the incoming HTTP headers and validates the signature before returning the caller's `ScopeId`.

## 6. Known Limitations

1. **Branch coverage below target (79.88%):** The uncovered branches are deep HTTP error paths (msgpack decode failure on a 200 response, generic request error fallthrough) that are hard to trigger deterministically in integration tests.
2. **No TLS:** The current implementation targets local‑network/insecure deployments. TLS can be added via `createSecureServer`.
3. **Single‑hop only:** The transport does not implement relay forwarding; mesh messages are direct peer‑to‑peer.
